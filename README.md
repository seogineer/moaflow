## 1. 서비스 기획안 (Plan)

# 모아플로우: 흩어진 할 일을 한 장의 실행 목록으로

## 해결할 문제

작은 팀이나 개인은 메신저, 노트, 이슈 트래커에 할 일이 흩어져 있다는 이유로 같은 일을 두 번 하거나, 마감과 다음 행동을 놓치곤 합니다. 특히 같은 요청이 여러 도구에 복사되면 누가 맡았는지 불명확해지고, 메일 발송이나 게시 같은 외부 행동은 승인 여부를 놓치기 쉽습니다.

**모아플로우**는 사용자가 서로 다른 도구에서 복사한 할 일 조각을 한 작업함으로 모아, 중복 후보·기한·위험한 외부 행동을 확인하고 다음 순서를 제안하는 멀티 에이전트 서비스입니다. 첫 PoC는 모든 직무에 공통된 “흩어진 요청 정리와 누락 방지” 문제에 집중합니다.

## 사용자와 사용 흐름

주요 사용자는 3~5인 초기 스타트업·프로젝트 팀의 구성원입니다. 이들은 슬랙, 메신저, 메일, 노션에서 같은 요청을 각각 받습니다. 예를 들어 월요일 아침에 “견적서 보내줘”(슬랙), “견적서 발송 건 확인”(메일)이 따로 도착하면, 두 사람이 같은 일을 하거나 아무도 하지 않습니다.

사용 흐름은 세 단계입니다.
1. **붙여 넣기:** 사용자가 여러 채널의 원문을 한 번에 붙여 넣습니다.
2. **추출·정리:** 모아플로우가 원문에서 할 일과 기한을 뽑고, 의미가 같은 항목을 중복 후보로 연결합니다.
3. **실행 계획:** 사용자가 **에이전트 팀 실행**을 누르면 순서와 이유를 제안합니다. 메일·게시·제출·결제·전화·삭제처럼 외부에 영향을 주는 일은 “승인 필요”로 표시합니다. PoC는 어떤 외부 행동도 실제 실행하지 않습니다.

**데모 결과(재현 가능):** 원문 10줄을 붙여 넣으면 할 일 7건을 추출하고, 중복 후보 2건을 연결하고, 외부 행동 4건(견적서 발송 2건, 릴리스 노트 게시, 안내 메일 발송)을 승인 대기로 멈춥니다. 견적서 2건은 중복 후보이므로 사람이 먼저 하나로 합친 뒤 승인합니다.

## 멀티 에이전트 구조

1. **수집 에이전트** — 입력 항목의 제목, 출처, 기한을 정리합니다.
2. **중복 탐지 에이전트** — 유사한 항목을 대표 작업에 연결해 이중 착수를 줄입니다.
3. **계획 에이전트** — 기한과 작업 상태를 바탕으로 다음 행동과 우선순위를 설명합니다.
4. **안전 에이전트** — 되돌리기 어려운 외부 행동을 탐지해 사람의 승인 대기 상태로 둡니다.
5. **조정자 UI** — 에이전트 결과를 한 화면에 보여 주며, 최종 판단은 사용자에게 남깁니다.

**AI는 제안하고, 규칙은 보장합니다.** 생성형 AI는 두 곳에 쓰입니다.
- **수집 에이전트:** 붙여 넣은 긴 원문에서 할 일과 기한을 추출합니다. 이 부분은 규칙으로 만들기 어렵습니다. 문장 형태와 날짜 표현이 제각각이기 때문입니다.
- **계획 에이전트:** 다음 행동과 이유를 자연어로 설명합니다.

AI 결과가 나온 뒤에는 결정적 규칙이 항상 다시 실행됩니다. 안전 에이전트는 계획 에이전트 뒤에서 최종 권한을 가집니다. AI가 “지금 메일 발송 실행”이라고 답해도, 승인 필요 항목은 “초안만 준비하고 승인 대기”로 강제됩니다. AI가 항목을 빠뜨리면 규칙 기반 계획으로 보충합니다. 이 구조 덕분에 모델의 추측만으로 외부 행동이 일어나지 않습니다.

PoC는 외부 전송이 없는 로컬 데모가 기본입니다. 로컬 모드의 추출은 규칙 기반이며, AI를 연결하면 추출 품질이 올라갑니다. API 주소·키·모델을 모두 명시해야 AI 모드가 켜지며, 켜지면 화면 상단에 “입력 텍스트가 AI 제공자로 전송됨”이 표시됩니다.

## PoC 범위와 기술

`index.html`, `styles.css`, `app.js`는 모바일 대응 단일 화면입니다. 브라우저 `localStorage`에 입력 업무를 저장하고, Python 표준 라이브러리 서버가 원문 추출(`/api/extract`)과 계획(`/api/plan`)을 맡고, Intake → Deduplication → Planner → Safety 파이프라인을 실행합니다. AI API가 연결되지 않으면 규칙 기반 데모 플랜을 만듭니다. 연결 시에는 입력 업무 텍스트가 설정된 API 제공자에게 전송된다는 사실을 화면과 실행 안내에 고지합니다. 외부 SaaS 로그인·동기화, 실제 발송·게시·제출, 회원 정보 수집은 범위에서 제외합니다.

## 성공 기준

- 데모 원문 10줄에서 할 일 7건과 기한 5건 이상을 추출한다. (자동 테스트로 고정)
- 표현이 다른 같은 업무 2쌍을 중복 후보로 연결하되, 항목은 삭제하지 않는다.
- 외부 행동(메일 발송·게시·삭제·송금 등) 2건 이상을 승인 대기로 표시한다. 어떤 입력과 AI 응답에서도 자동 실행하지 않는다.
- AI 응답이 비정상이거나 안전 규칙을 어겨도, 최종 계획은 안전 규칙을 지킨다. (자동 테스트로 고정)
- 기한이 가까운 작업을 먼저 제안하고, 각 제안에 이유를 보여 준다.
- 데모 모드에서 인터넷/API 키 없이 작동하고, 모바일 폭에서도 핵심 흐름이 사용 가능하다.

## 생성형 AI 사용 및 한계

기획·코드 초안 작성 과정에 생성형 AI의 도움을 받았습니다. 현재 PoC 기본 실행은 재현 가능한 규칙 기반 데모이며, 설정된 AI 제공자를 선택적으로 연결할 수 있습니다. 따라서 데모 화면의 “에이전트”는 여러 역할로 분리된 처리 단계를 뜻하며, 별도 SaaS 에이전트나 실서비스 연동이 이미 구축되었다는 의미는 아닙니다. 모든 출력은 제안이며, 실제 업무 판단과 외부 행동의 승인 권한은 사용자에게 있습니다.

## 2. 멀티 에이전트 설계 및 아키텍처

# 모아플로우 개선 설계 (v2)

기준: `docs/plan.md`(기획안), 검증 보고(Major 7건, Minor 7건). 이 문서는 developer·tester·verifier의 작업 기준이다.

## 1. 목표

1. 사용자가 붙여 넣은 원문(메신저·메일·메모)에서 할 일, 기한, 출처를 추출한다. (신규 `/api/extract`)
2. AI는 제안하고, 규칙은 보장한다. LLM 결과 뒤에 Safety 규칙을 항상 다시 적용한다.
3. 문서·trace·UI 고지를 실제 동작과 일치시킨다.
4. 검증에서 나온 Major 7건을 모두 고친다. Minor는 아래 표의 항목만 고친다.

## 2. 파이프라인 (확정 순서)

`Intake → Deduplication → Planner → Safety(후처리)`

- Safety는 Planner 뒤에 한 번 더 실행한다. 이 단계가 최종 권한을 가진다.
- Safety 후처리 규칙: `requires_approval`인 항목의 `action`을 `"초안만 준비하고 승인 대기"`로 강제한다.
- Planner 결과(LLM 포함)는 모든 `task_id`를 정확히 한 번씩 포함해야 한다. 빠진 항목은 로컬 계획으로 보충한다. 중복 `task_id`는 첫 항목만 남긴다.
- `agent_trace`는 위 순서와 같게 만든다. 이름은 `Intake`, `Deduplication`, `Planner`, `Safety`다.

## 3. API

### 3.1 `POST /api/extract` (신규)

요청: `{"text": "<원문>", "source": "슬랙|노션|깃허브|메신저|기타"}`
- `text`는 최대 8,000자. 초과하면 413이 아니라 앞 8,000자만 사용한다.
- 응답: `{"tasks": [{"id","title","source","due"}], "engine": "local-demo|configured-llm"}`

로컬 규칙 추출(기본):
1. 줄바꿈과 문장 종결(`.`, `。`, `?`, `!`, `다.`)로 나눈다. 빈 조각과 인사말(안녕하세요 등 6자 미만)은 버린다.
2. 작업 표현이 있는 조각만 남긴다. 표현 목록: `해주세요, 해 주세요, 부탁, 까지, 필요, 확인, 작성, 정리, 준비, 보내, 발송, 제출, 공유, 요청, please, need, todo` 등. 목록은 상수 한 곳에 둔다.
3. 기한을 추출한다. 지원 형식: `YYYY-MM-DD`, `M/D`, `M월 D일`, `오늘`, `내일`, `모레`, `이번 주 금요일`, `다음 주 금요일`, `금요일`(다음에 오는 가장 가까운 해당 요일). 기준일은 KST 오늘이다. 못 찾으면 빈 문자열이다.
4. `id`는 `ext-1`, `ext-2` 순으로 만든다.

LLM 추출(`AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`이 모두 설정된 경우만):
- 시스템 프롬프트로 JSON `{"tasks":[{"title","due"}]}`만 요구한다.
- 응답은 dict인지, `tasks`가 list인지, 각 항목의 `title`이 문자열인지 확인한다. 검증은 `normalize_tasks`를 통과시킨다.
- 어떤 오류든 로컬 규칙 추출로 폴백한다. 400을 내지 않는다.

### 3.2 `POST /api/plan` (변경)

- 응답에 `engine_status`를 추가한다: `{"mode": "local-demo|configured-llm", "sends_text_to_provider": bool}`.
- LLM Planner 응답 검증을 강화한다.
  - 최상위가 dict가 아니면 폴백한다.
  - `steps`가 list가 아니면 폴백한다.
  - 모든 `task_id`가 정확히 한 번씩 있지 않으면 빠진 항목을 로컬 계획으로 보충한다.
  - 응답 본문은 최대 256KB만 읽는다.
- 중복이면서 승인 필요인 항목은 `reason`에 두 사유를 모두 쓴다.

### 3.3 공통 오류 처리

- `Content-Length`가 정수가 아니면 400을 보낸다.
- 본문이 UTF-8이 아니면 400을 보낸다.
- `Content-Type`이 `application/json`이 아니면 415를 보낸다.
- `Origin` 헤더가 있으면 `Host`와 같은 출처여야 한다. 아니면 403을 보낸다.
- `except`는 `(ValueError, AttributeError, TypeError)`를 잡는다. `JSONDecodeError`와 `UnicodeDecodeError`는 `ValueError`의 하위 클래스다.
- 서버는 어떤 입력에도 응답 없이 연결을 끊지 않는다.

## 4. 정적 파일 허용 목록 (Major 4)

`do_GET`/`do_HEAD`는 아래 경로만 제공한다. 나머지는 404다.

`/`, `/index.html`, `/app.js`, `/styles.css`, `/docs/plan.md`

디렉터리 목록은 제공하지 않는다.

## 5. 승인 키워드 (Major 5, Minor 1)

- 키워드 목록을 `server.py`의 `APPROVAL_TERMS` 한 곳에 둔다.
- 추가 키워드: `지우, 제거, 송금, 이체, 환불, 공유, 초대, remove, transfer, refund, share, wire`.
- 영문 키워드는 단어 경계 정규식 `\b`로 매칭한다. 한글 키워드는 부분 문자열로 매칭한다.
- 오탐 방지 대상: `recall`, `facebook`, `postmortem`은 승인 필요가 아니다. `메일함 읽기`는 승인 필요가 아니다. 이를 위해 한글 `메일`은 `메일 보내|메일 발송|메일로|메일을`처럼 동작 표현과 함께 있을 때만 매칭한다. 구현은 developer가 정하고 테스트로 고정한다.
- 클라이언트(`app.js`)는 자체 키워드 목록을 두지 않는다. 서버 응답의 `requires_approval`만 쓴다. 분석 전에는 승인 개수를 `-`로 표시한다.

## 6. 고지와 설정 (Major 7)

- `AI_BASE_URL`은 필수다. 기본값 `api.openai.com`을 제거한다. 세 변수 중 하나라도 없으면 로컬 모드다.
- 시작 메시지는 현재 모드(local-demo / configured-llm)와 전송 여부를 출력한다.
- `index.html`의 `privacy-pill`은 고정 문구를 쓰지 않는다. 서버가 준 `engine_status`로 바꾼다.
  - local-demo: `로컬 데모 · 외부 전송 없음`
  - configured-llm: `AI 연결됨 · 입력 텍스트가 AI 제공자로 전송됨`
- 페이지 로드 시 `GET /api/status`(신규, `engine_status` 반환)를 호출해 pill을 초기화한다. 이 경로도 허용 목록에 추가한다.

## 7. UI 변경

1. Inbox 패널 위쪽에 **원문 붙여넣기** 영역을 둔다. 큰 textarea(최대 8,000자)와 `할 일 추출` 버튼이다.
2. 버튼을 누르면 `/api/extract`를 호출한다. 결과 항목을 작업함에 추가한다. 기존 한 건 입력 폼은 유지한다.
3. 데모 버튼은 작업함을 비우고 데모 원문 10줄(§8)을 원문 영역에 채운다. 작업함이 비어 있지 않으면 첫 클릭은 안내만 한다.
4. `innerHTML`은 정적 문자열에만 쓴다. 동적 값은 `textContent`로 넣는다. (현재 동작 유지)
5. 계획 표시는 8단계 제한을 없앤다. 8개를 넘으면 `더 보기` 버튼으로 펼친다.
6. `localStorage` 항목은 읽을 때 검증한다. `id`, `title`, `source`, `due`가 모두 문자열인 항목만 쓴다. 나머지는 버린다.
7. 클라이언트 중복 계산(`localDuplicateGroups`)은 제거한다. 서버 결과의 `duplicate_of`만 표시한다. 분석 전에는 중복 개수를 `-`로 표시한다.
8. 기존 `task_id` 충돌은 서버가 해결한다(§9).

## 8. 데모 시나리오 (수치 기준)

원문(슬랙·메일·메신저를 섞은 약 10줄)을 `docs/demo_input.txt`에 저장한다. 기대 결과는 아래다. 테스트가 이 수치를 고정한다.

| 지표 | 값 |
|---|---|
| 원문 줄 수 | 10 |
| 추출된 할 일 | 7 |
| 중복 후보 | 2 |
| 승인 필요 | 정확히 4 (견적서 보내줘, 견적서 발송 건, 릴리스 노트 게시, 안내 메일 발송) |
| 기한 추출 | 5 이상 |

원문은 다음을 반드시 포함한다.
- 같은 일을 다르게 쓴 쌍 2개 (예: "견적서 보내줘", "견적서 발송 건 확인").
- 외부 행동 2개 (메일 발송, 팀 채널 게시).
- 인사말 1~2줄 (추출 대상이 아님).
- 상대 기한 표현 (`오늘`, `내일`, `모레`, `금요일`, `다음 주 월요일`). 절대 날짜(`11/20`, ISO)는 데모 원문에 넣지 않고 단위 테스트로만 검증한다.

기대 수치는 로컬 모드에서 재현되어야 한다. 구현 후 실제 수치가 다르면 원문을 조정하고 이 표를 실제 값으로 갱신한다.

## 9. 중복과 ID (Minor 2, 3, 4)

- `normalize_tasks`는 ID가 중복이면 접미사 `-2`, `-3`을 붙인다.
- 불용어 목록은 서버만 가진다.
- 중복 탐지는 기존 토큰 유사도를 유지하되, 동의어 표를 추가한다. 예: `{보내,발송,전달}`, `{견적서,견적}`, `{정리,작성,초안}`. 같은 집합 안의 단어는 같은 토큰으로 정규화한다. 표는 `server.py` 한 곳에 둔다.
- 설정된 LLM이 있으면 `/api/plan` 중복 판단은 규칙 결과를 유지한다. 중복 추가 판단은 범위 밖이다. (결정적 규칙 우선 원칙)

## 10. 테스트 기준 (tester)

`tests/test_server.py`를 확장한다. 모든 테스트는 `setUp`에서 `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`을 제거해 실제 API 호출을 막는다.

필수 케이스:
1. 추출: 데모 원문 → §8 수치. 기한 파싱(`내일`, `금요일`, `11/20`, ISO). 인사말 제외. 8,000자 초과 절단.
2. Safety: 삭제·송금·환불 표현 감지. `recall`, `facebook`, `메일함 읽기`는 비감지.
3. LLM 경로(`urllib.request.urlopen` mock):
   - 응답이 `[1,2]`이면 로컬 폴백.
   - 승인 필요 항목에 "지금 바로 메일 발송 실행"을 주면 Safety 후처리가 `초안만 준비하고 승인 대기`로 바꾼다.
   - 항목을 빠뜨리면 로컬 계획으로 보충한다. 중복 `task_id`는 한 번만 남는다.
   - 연결 오류면 로컬 폴백.
4. HTTP(실제 `ThreadingHTTPServer`를 포트 0으로 띄움):
   - 잘못된 JSON, 리스트 본문, `Content-Length: abc`, 비 UTF-8 → 모두 400이며 응답이 온다.

   - `/api/status`가 모드를 돌려준다.
5. 순서: `agent_trace` 이름 순서가 `Intake, Deduplication, Planner, Safety`다.
6. ID 충돌: 같은 ID 두 개 → 접미사가 붙는다.

## 3. PoC 구현체 및 빠른 시작 (Quick Start)

# 모아플로우 — 엘리스 AI 챌린지 PoC

흩어진 할 일을 한곳에 모아 중복 후보와 마감 우선순위를 정리하고, 메일·게시·제출 같은 외부 행동은 사람의 승인 전까지 멈추는 멀티 에이전트 업무 정리 프로토타입입니다.

- **기획안:** [`docs/plan.md`](docs/plan.md)
- **PoC:** `index.html` + `app.js` + `styles.css` + `server.py`
- **대회 안내:** [2026 엘리스 AI 챌린지 공식 페이지](https://ai-challenge.elice.page/home/main)

## 실행

Python 3 표준 라이브러리만 필요합니다.

```bash
cd 02-elice-ai-challenge
python3 server.py
```

브라우저에서 `http://127.0.0.1:8787`을 엽니다. 작업함은 빈 상태로 시작합니다. **데모 원문 채우기**를 누르고 **할 일 추출**, **에이전트 팀 실행** 순서로 누르세요. 할 일 7건, 중복 후보 2건, 승인 필요 4건이 나옵니다. 작업함에 항목이 있으면 **데모 원문 채우기**가 화면 안 안내를 먼저 보여 주고, 한 번 더 누르면 작업함을 비웁니다. 작업함은 이 브라우저의 `localStorage`에 저장됩니다. 서버는 요청 본문(업무 텍스트)을 로그에 남기지 않습니다. 데모 원문은 [`docs/demo_input.txt`](docs/demo_input.txt)에 있습니다.

## 에이전트 흐름

`Intake → Deduplication → Planner → Safety` 순서로 실행합니다.

1. **Intake** — 붙여 넣은 원문에서 할 일·기한·출처를 추출하고 항목을 정리
2. **Deduplication** — 유사 항목을 중복 후보로 연결 (원본 항목은 삭제하지 않음, 동의어 표 적용)
3. **Planner** — 기한과 중복 여부를 바탕으로 다음 행동을 제안
4. **Safety** — Planner 뒤에 한 번 더 실행하는 최종 규칙. 외부 발송·게시·제출·결제·삭제·송금 등은 LLM 결과와 관계없이 `초안만 준비하고 승인 대기`로 고정

AI는 제안하고, 규칙은 보장합니다. 승인 필요 여부는 서버가 판정하며 클라이언트는 서버 응답만 표시합니다.

## API

| 경로 | 설명 |
|---|---|
| `POST /api/extract` | `{"text","source"}` → `{"tasks":[{"id","title","source","due"}],"engine"}`. 원문은 8,000자까지 사용 |
| `POST /api/plan` | `{"tasks":[...]}` → `tasks`, `plan`, `agent_trace`, `engine_status` |
| `GET /api/status`, `HEAD /api/status` | `{"mode":"local-demo\|configured-llm","sends_text_to_provider":bool}` |

POST는 `Content-Type: application/json`이 필요합니다(아니면 415). `Origin` 헤더가 있으면 `Host`와 같아야 합니다(아니면 403). 잘못된 JSON·`Content-Length`·UTF-8은 400, 64KB 초과는 413입니다. 소켓 무응답은 10초 뒤 연결을 닫습니다. 정적 파일은 `/`, `/index.html`, `/app.js`, `/styles.css`, `/docs/plan.md`만 제공합니다.

## AI 연결과 환경변수

기본 모드(`local-demo`)는 외부 호출이 없는 재현 가능한 규칙 기반 데모입니다. OpenAI 호환 모델을 연결하려면 세 변수를 **모두** 설정하세요. 하나라도 없으면 로컬 모드입니다. `AI_BASE_URL`에는 기본값이 없습니다.

```bash
export AI_BASE_URL="https://api.example.com/v1"
export AI_API_KEY="<your key>"
export AI_MODEL="<provider model id>"
python3 server.py
```

연결하면(`configured-llm`) 추출·계획에 쓰는 입력 텍스트가 해당 API 제공자에게 전송됩니다. 화면 상단 표시와 서버 시작 메시지가 현재 모드와 전송 여부를 알려 줍니다. 키를 코드나 저장소에 넣지 마세요. 호출이 실패하거나 응답 형식이 올바르지 않으면 로컬 규칙으로 되돌아갑니다. PoC는 실제 이메일 발송·게시·제출·결제·삭제, 외부 SaaS 동기화를 하지 않습니다.

## 범위와 AI 사용 고지

생성형 AI의 도움으로 기획·코드 초안을 작성했습니다. 기본(local-demo) 모드의 런타임 에이전트는 로컬 규칙 기반입니다. AI를 연결하면 추출·계획 제안에 외부 LLM을 쓰지만 Safety 규칙이 최종 권한을 가집니다. 별도 서비스 계정 연동이나 외부 실행은 구현하지 않았습니다. 제출 전에는 공식 공지의 제출 형식·마감·AI 활용 기재 요건을 다시 확인하세요.
